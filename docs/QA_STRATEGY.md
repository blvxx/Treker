# QA-стратегия «Вдох»

## 1. Цели качества

- Не терять пользовательский прогресс.
- Не смешивать демо-данные и реальные записи.
- Корректно считать время, экономию, статистику и серии.
- Безопасно обрабатывать пользовательский ввод.
- Не допускать доступа к чужим данным.
- Не применять AI-изменения без согласия пользователя.
- Сохранять доступность основных сценариев на web и mobile.

## 2. Уровни тестирования

### Unit
- расчёт длительности отказа;
- расчёт ориентировочной экономии;
- календарные границы и часовые пояса;
- серии привычек и пропущенные дни;
- валидация порций и пищевой ценности;
- валидация планов тренировок;
- миграция локальных данных.

### Integration / API
- регистрация и авторизация;
- CRUD привычек;
- журнал recovery;
- синхронизация;
- экспорт/удаление данных;
- AI gateway и проверка структурированных ответов;
- Telegram account linking и обработка webhook.

### UI / E2E
- первый запуск;
- настройка даты отказа от курения;
- запись тяги;
- дыхательная практика: старт, пауза, остановка;
- создание и выполнение привычки;
- смена языка;
- работа на мобильном viewport;
- восстановление состояния после перезагрузки.

### Security / Privacy
- IDOR и изоляция пользователей;
- XSS через заметки и названия привычек;
- CSRF/session handling, где применимо;
- rate limiting;
- секреты отсутствуют в клиентском bundle;
- prompt injection и попытки извлечения чужого контекста;
- согласие и минимизация данных, передаваемых AI.

## 3. Начальные критические сценарии

1. Новая установка не должна выдавать демонстрационные записи за реальные.
2. Обновление приложения не должно удалять существующее состояние `vdoh.v1`.
3. Некорректный JSON в хранилище не должен приводить к белому экрану.
4. Экспорт содержит пользовательские данные и корректно открывается как JSON.
5. Сброс требует явного подтверждения.
6. Заметка с HTML/JavaScript отображается как текст, а не исполняется.
7. Повторный клик по отметке привычки не создаёт дубликат.
8. Пропуск дня не удаляет историю.
9. Смена ru/en не меняет сохранённые значения и даты событий.
10. Ошибка AI API не должна менять данные пользователя.
11. AI-рекомендация не применяется без подтверждения.
12. Telegram-пользователь не может обратиться к данным другого аккаунта.

## 4. Инструменты

- Pytest — backend и API.
- Playwright — web E2E.
- Maestro — mobile E2E, когда появится мобильный клиент.
- GitHub Actions — автоматические проверки pull request.
- Coverage — контроль покрытия критичной бизнес-логики.

## 5. Definition of Done

Функция считается готовой, если:

- описаны требования и критерии приёмки;
- обработаны валидные, невалидные и граничные данные;
- есть автоматические тесты критичной логики;
- нет открытых blocker/critical дефектов;
- интерфейс проверен на desktop и mobile;
- ошибки и пустые состояния понятны;
- данные не раскрываются другим пользователям;
- документация обновлена.
