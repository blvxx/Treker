# QA-стратегия «Вдох» — Android-first

## 1. Цели качества

- Не терять пользовательский прогресс.
- Не смешивать демонстрационные и реальные записи.
- Корректно считать время, экономию, статистику и серии.
- Безопасно обрабатывать пользовательский ввод.
- Не допускать доступа к чужим данным.
- Не применять AI-изменения без согласия пользователя.
- Обеспечить стабильность на поддерживаемых Android-устройствах и размерах экранов.
- Проверять offline-first поведение, системные разрешения и уведомления.

## 2. Уровни тестирования

### Unit
- расчёт длительности отказа;
- расчёт ориентировочной экономии;
- календарные границы, часовые пояса и локали;
- серии привычек и пропущенные дни;
- валидация порций и пищевой ценности;
- валидация планов тренировок;
- миграции локальных данных;
- правила синхронизации и разрешения конфликтов.

### Component / UI
- React Native Testing Library;
- формы и валидация;
- состояния загрузки, пустого списка и ошибок;
- смена ru/en;
- доступность TalkBack labels и масштабирование текста.

### Integration / API
- регистрация и авторизация;
- CRUD привычек;
- журнал recovery;
- синхронизация;
- экспорт/удаление данных;
- AI gateway и проверка структурированных ответов;
- Telegram account linking и обработка webhook.

### Mobile E2E
- Maestro для Android E2E;
- первый запуск и onboarding;
- настройка даты отказа от курения;
- запись тяги;
- дыхательная практика: старт, пауза, остановка;
- создание и выполнение привычки;
- смена языка;
- работа в offline/online;
- перезапуск приложения и восстановление состояния;
- разрешение/отказ в разрешении уведомлений;
- обновление приложения без потери пользовательских данных.

### Device / Release
- проверка на реальном Android-устройстве;
- разные размеры экранов и плотности;
- холодный старт и обновление;
- поведение при нехватке памяти и прерывании процесса;
- фоновые ограничения и точность напоминаний с учётом Android Doze;
- smoke test подписанной AAB/APK сборки.

### Security / Privacy
- IDOR и изоляция пользователей;
- небезопасное хранение токенов и секретов;
- отсутствие AI API keys и signing keys в клиентском bundle/repository;
- rate limiting;
- prompt injection и попытки извлечения чужого контекста;
- согласие и минимизация данных, передаваемых AI;
- безопасный экспорт, удаление аккаунта и локальных данных.

## 3. Начальные критические сценарии

1. Новая установка не должна выдавать демонстрационные записи за реальные.
2. Миграция старого экспорта Treker не должна молча терять данные.
3. Некорректные или повреждённые локальные данные не должны приводить к потере всего профиля.
4. Экспорт содержит пользовательские данные и корректно открывается как JSON.
5. Сброс требует явного подтверждения.
6. Заметка с HTML/JavaScript отображается как обычный текст.
7. Повторный тап по отметке привычки не создаёт дубликат.
8. Пропуск дня не удаляет историю.
9. Смена ru/en не меняет сохранённые значения и даты событий.
10. Ошибка AI API не должна менять данные пользователя.
11. AI-рекомендация не применяется без подтверждения.
12. Telegram-пользователь не может обратиться к данным другого аккаунта.
13. Отказ в разрешении уведомлений не ломает основные функции.
14. Потеря сети не приводит к потере локально сохранённых действий.
15. После обновления приложения пользовательские данные остаются доступными.

## 4. Инструменты

- Jest — unit tests для TypeScript.
- React Native Testing Library — component tests.
- Pytest — backend и API.
- Maestro — Android E2E.
- GitHub Actions — lint, typecheck, tests и сборочные проверки.
- Coverage — контроль покрытия критичной бизнес-логики.

## 5. Definition of Done

Функция считается готовой, если:

- описаны требования и критерии приёмки;
- обработаны валидные, невалидные и граничные данные;
- есть автоматические тесты критичной логики;
- нет открытых blocker/critical дефектов;
- интерфейс проверен на целевом Android-устройстве;
- ошибки и пустые состояния понятны;
- данные не раскрываются другим пользователям;
- разрешения и уведомления работают корректно;
- документация обновлена.
