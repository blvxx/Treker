# Дорожная карта разработки «Вдох»

Основной продукт — Android-приложение. Первая публичная площадка — Google Play. Сначала private testing, затем закрытое/открытое тестирование по необходимости и production release. Веб-клиент не является целью текущей дорожной карты.

- [x] Проверить состав репозиториев.
- [x] Подтвердить Treker как источник текущих recovery-функций.
- [x] Зафиксировать, что HabitForge пока содержит только README.
- [x] Создать отдельную рабочую ветку для подготовки.

- [ ] Зафиксировать baseline ручными тестами.
- [ ] Утвердить Android-first архитектуру и структуру мобильного приложения.

## Этап 1 — стабилизация и перенос Treker

- [ ] Зафиксировать сценарии текущего Treker тест-кейсами.
- [ ] Выделить чистую бизнес-логику таймера, расчётов, журнала тяги и дыхательных практик.
- [ ] Не пытаться напрямую использовать браузерный HTML/CSS в React Native.
- [ ] Перенести и адаптировать проверенную логику в TypeScript-модули.
- [ ] Определить схему локальных данных и миграцию старого экспорта JSON.
- [ ] Сохранить оригинальный Treker как reference и fallback; не удалять исходную реализацию.

## Правило выполнения

Каждый этап завершается работающей сборкой, тестами и обновлённой документацией. Не переходить к масштабным AI и backend-функциям до стабилизации локального mobile MVP. Не обещать дату публикации, пока не проверены реальные требования Google Play и качество сборки.
